## 基本概念-Part1

**强化学习的基本概念，包括两部分内容** 

第一部分 通过例子介绍概念

第二部分 把这些概念以一种更加正式的方式给介绍出来，并且是在Markov decision process框架下

### grid-world example

首先 本节课会广泛使用的一个例子：grid-world example

**什么是grid-world?** 

一个网格世界，然后有一个机器人在里边走，这里边的每一个小的网格，它们有不同的类型：

- 比如说有的网格是accessible 就是可以进去的，用白色来表示
- 另外是forbidden 用黄色来表示
- 另外是target area 我们希望它能够进到这个领域当中
- 此外，这个网格世界是有一个边界的，也就是这个边界，不同机器人，可以在相邻的这个块中间移动 不能在斜的方向进行移动。

**我们为什么要考虑这样一个例子呢？**

用它来介绍很多概念的时候会非常地清晰

**强化学习这个例子当中的任务是什么呢？** 

就是它要找到一个比较好的a good way to the target，比如说它从这个地方出发，它希望能够找到一个比较好的路径到达目标，这个就是grid-world example的一个任务

**这里边有一些问题，比如说我怎么样去定义一个路径究竟是好还是坏？**

这个其实是一个非常核心的问题，之后我们会详细定义

**什么是最优的策略 最优的路径？**

但是直观上来说我们其实可以回答，比如说 尽可能地要避免这些forbidden area尽可能地不要进去；比如说 不要有没有意义的拐弯，比如说它本来要进到target area，它先走到这，然后又回去又过来又回去绕来绕去的，这种应该避免；另外就是不要试图超越边界，比如说它要往上走或者往左走，这样的话 也应该是避免的。

**下面我们用这个例子，来介绍我们整门课程当中的第一个概念** 什么呢？

### state 

**State其实描述的就是agent相对于环境的一个状态 status**

**然后在grid-world example当中state指的是什么呢？**

就是指的location，这里边有s1 s2 s3一直到s9 有这么多个location，我们就用s1 s2 s9这些字母来代替来表示这些状态

> 这些字母 比如说 s1 实际上它是一个索引，它真正对应的状态 这里面当然是在二维平面上的位置，x方向的位置x和y方向的位置y，如果是更加复杂的问题，有可能除了位置之外还要对应速度；如果是机器人的话 还要对应加速度等等，或者是其他类型当中的状态信息
>

好 这个是状态，如果我们把所有的状态放到一起，我们就得到了 状态空间 state space

**空间这个词 大家可能第一次听说的时候，会感觉 非常的高大上 线性空间什么的，实际上不用这么害怕，**其实这空间其实就是一个集合 set，什么意思呢？

我们用这个花的$\mathcal{S}$来表示状态空间, 它就是把所有的状态si给放到一起得到的一个集合，我们两边的花括号代表的就是一个集合，有时候我们会在后面给出$i$等于什么什么，有时候如果我们不给的话，大家也可以从上下文来直接得到$i$的范围

下一个概念 

### Action

非常重要的概念 非常基本的一概念

**Action是什么呢？**

就是我在每一个状态实际上是有一系列的可采取的行动，在这个里面一共有5个行动 a1到a5

**具体来说是什么？**

a1就是要从这个状态往上走，a2是往右走，a3是往下走，a4是往左走，a5就是原地不动，这里a5是用一个圆圈来表示

**如果我把所有的这些action放到一起我就得到了什么呢?** 

Action space

Action space我们用一个花的$\mathcal{A}$来表示，和前面一样实际上这是一个集合
然后我把所有的 a 放到了一起

**值得指出的是** action space 它和状态是依赖的，也就是不同状态，它的action space是不一样的，所以这个就是我们为什么这里要一个括号 $s_i$
这就表示 $\mathcal{A}$ 实际上是$s_i$的这样一个函数

$\mathcal{A}(s_i)=\{a_i\}_{i=1}^5$

### State transition

**<u>*下一个概念 State transition*</u>**  

这是什么意思呢？就是当我采取一个action的时候，这个agent可以从一个state移动到另一个state，这样的过程就被称为state transition；

我们举一个例子，比如说在状态s1，如果我采取action是a2，刚才我们提到了a1是向上，a2是向右，a3是向下，a4是向左，a5是原地不动，之后我们会频繁地用到，所以我希望大家能够把这个放到脑子里边记一下

所以我在s1，然后我a2是要往右走，下一个状态是什么呢？我就会跳到s2
所以这样一个过程就可以用这个式子来表示出来 $s_1 \xrightarrow{a_2} s_2$ ，我在s1 我take a2 然后跳到s2

**我们看另外一个例子**

我在s1 然后我take action a1，a1是什么？ 就是往上走，下一个状态是什么呢？，s1 a1下一个状态是s1，这是怎么回事呢？我在s1然后我要往上走 我会撞到这个边界是吧？，如果边界是一堵墙的话 我会被撞回来，就还是回到s1，我不会出去，所以这个是这种情况下的state transition

**State transition实际上是定义agent和环境的一种交互的行为**

我们在这里边能不能用其他的方式来定义这种交互的行为呢？

首先因为这是一个仿真，因为这是一个游戏，实际上我们可以任意地定义
比如说我刚才是往上走的时候撞到墙了，我会被弹回来，也可能会被弹到这边去，下一个状态是s4，甚至可能会被弹到这边去，下一个状态是s7，因为它是游戏 是想怎么定义就怎么定义，但是在实际当中并不是这个样子

比如说机器人就在这边，然后它要往那边移动一点，那它不可能想跑到哪个状态都跑到哪个状态，所以实际当中 我们不能任意定义，但是在游戏当中其实我们是可以的

**我们下面来关注一下Forbidden area**

比如说我们在s5 然后我们take action a2 就是往右走，下一个状态是什么？
其实这里边是有两种情况，

**第一种情况** Forbidden area，虽然它是静止的，但是它仍然是可以进去的，只不过进去的时候会被惩罚，所以它是可以进去
那这时候我在s5 take a2，下一个状态就是s6，也就是它进到这里边了

**第二种情况是什么？**

就是forbidden area物理上它就是无法进入的，比如说它周围是装上了墙，怎么都进不去，那这时候s5，然后a2，那它就会被弹回来，又回到了s5

**在我们课程当中，我们考虑的是第一种情况，也就是考虑这种情况** 

我们认为forbidden area虽然是forbidden，但是它可以进去，只不过它会得到惩罚，这种情况相比第二种情况，实际上是更加地一般化也更加难

**为什么？**

因为如果我把一些状态给排除掉的话 状态空间就小了，实际上我做搜索的时候会更加容易，如果我们认为这个forbidden area是可以进去的话，其实还会出现比较有意思的一些现象：
比如说，虽然进去forbidden area会得到惩罚，但是也许进去之后，进到target area反而是最近的路径，所以有可能agent会冒险进到这个forbidden area，然后通过forbidden area再到target area，所以这个会带来一些比较有意思的这种行为，那么之后 我们会介绍这些。

**State transition可以用这种tabular的形式表现出来** 

有这样一个表格，这个表格的每一行 都对应了每一个状态，这个表格的每一列 都对应了这样一个action

![image-20260508134351829](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605081659349.png)

比如说我在s1 我take action a1就是往上走，我会被弹回来，下一个状态就是s1，这里边任何的所有的每一个状态每一个action它都有定义，虽然这个表格的形式是比较直观的，但是在实际当中用的是比较受限

**为什么？** 

因为它只能表示这种deterministic，也就是确定性的情况，比如说我在s1 然后我take action a1，我也有可能跑到s1 我也可能被弹回到s4，我甚至可能被弹回到s7，也就是说有多个状态存在这样的可能性，这时候这个表格是无法表达的

**所以这时候其实我们更一般的方法是什么呢？**

用state transition probability，这是我们第一次把probability引进到里边
这个的直观是什么？比如说我在s1，我take action a2，也就是我要往右走 下一个状态就是s2，所以这个是一个语言的叙述，一个直观。它的数学是什么呢？数学我们就用conditional probability 条件概率

![image-20260508134510891](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605081659351.png)

那就是说如果现在我是在s1，并且我现在take action a2，那么我下一个时刻我跳到s2的概率是多少？这时候它告诉我们它的概率是1

同样的，我在s1 我take action a2，我下一个时刻跳到si，如果$i$不等于2 也就是跳到其它任意一个状态的概率是多少呢？是$0$，这个就是用条件概率来描述state transition，当然这里边仍然是一个确定性的一个例子

但是条件概率是能来描述这种随机性的这种例子

比如说有风，刚才我们说了它从这边，然后它要往右走，它会到s2，因为有风的原因，它可能50%的概率跑到这，50%的概率跑到s5，所以这时候我们就可以写成  p(s2|s1,a2)=0.5；然后，它跳到s5的概率也等于0.5，所以这时候它就可以用概率的形式来描述，随机的这样一个state transition

<u>所以概率的形式是更加地一般化</u> 

好，下面我们来介绍一个非常重要的概念

### Policy

**Policy，这个是强化学习当中 也是独有的一个概念** 

Policy是什么？

就是它会告诉agent， 我如果在一个状态我应该take哪一个action，直观上的理解policy，我们是用箭头来表示的，大家可以看到这里边有9个状态，每一个状态都对应一个箭头，当然这个不是箭头，这个是对应一个圆圈，它代表是待在原地不动，那么这样一个策略我就可以用箭头来表示

基于这个策略，实际上我们可以得到一些path或者叫trajectory，这个之后我们会再详细地介绍

<u>但是这边我们先通过一些直观来展示给大家，什么是path或者trajectory？</u>

假如说我从这边走，这个绿色的箭头就是策略，我在这的时候，这个策略告诉我，我应该往右走，根据刚才的stated transition probability，我下一个时刻我就会被跳到这边

我到这了之后这个策略，绿色的箭头，告诉我应该向下走，我往下走我就会跳到这个状态，然后依次类推，我这个策略让我往下走，我跳到这，策略让我往这边走，然后我到这，到这之后，这个策略让我就待在原地不动

所以我从这出发的话，我就会得到这样一个path；

如果我从这边出发的话，自然根据策略，然后再根据状态转移，我就会走到这边去，如果我从这边出发的话，我根据策略和状态转移，我就会走到这边去，也是比较直观的，刚才的策略是用箭头来表示

实际当中我们肯定对于稍微复杂一点的情况，我们都不能用这么直观的形式来表示，所以我们要用一种更加能够描述复杂情况一般化情况的一种方法，是什么呢？ 

就是数学的表达方式，仍然是用条件概率

我们举一个例子，针对$s_1$ ，它的策略 $π$ ，这里边的 π 一般情况下我们是指圆周率，但是在强化学习当中 π 就统一指的是策略

π是一个什么呢？ 它就是一个条件概率，它指定了任何一个状态下，任何一个action 它的概率是多少，比如说针对s1

- 在s1下它take action a1也就是往上走的概率是0
- 在s1下它take action a2也就是往右走的概率是1
- 其他所有的action的概率全都是0

它所有针对一个状态，它所有的概率之和应该加起来是等于1，这个就是一个策略

当然这里边我们只是说了这个s1，那还有s2一直到s9，也就是说对每一个状态我们都要有它的策略。

然后这个情况是什么呢？这个情况是一个确定性的情况，也就是我在s1我一定会take a2，**实际上也存在这种不确定性的情况，也就是stochastic的policy** 

比如说从这个地方出发，Policy 实际上有0.5的概率是要往右走，有另外0.5的概率是要往下走，如果这时候我从这个地方出发，有可能我得到的是这样一条轨迹，我也有可能得到是这样一条轨迹，所以这个时候策略是不确定的

我用刚才的条件概率的形式来表示其实也非常简单，我就是s1 我take a2的probability是0.5，s1 take a3的probability是0.5，它俩相加之和是等于1的

自然所有其它的action的probability全是0，所以有时候我们就省略掉了，但是大家知道，就是每一个action其实都有概率，只不过它是0而已。

好 这个策略也可以用这种表格的形式来表达出来

![image-20260508140809830](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605081659352.png)

比如说这个每一行都对应了一个状态，每一列都对应了一个action

我随便从里边，比如说s5 它采取往下走的这样一个action ，它的概率是多少呢？它的概率是1，所以这个对于s5来说，它是有一个确定性的策略；那么对于s1来说，它有0.5的概率是a2，0.5的概率是a3，所以对s1来说它是一个不确定性 stochastic的一个策略，这种表格实际上它是非常general的，它能够描述这种确定性的和这种随机性的情况

实际上我们在编程的时候就是这么做的，就是我们会用一个数组或者用一个矩阵来表示这样一个策略

另外我提一下就是在实际当中大家怎么样去执行策略，比如说我有0.5的概率是a2，0.5的概率是a3，那我在这个编程的时候，我怎么样去实现?其实也很简单，就是我们从0到1 进行一个随机的采样，比如说它是均匀分布
很多的软件都有这样的功能，然后我得到一个$x$，当这个$x$是属于$0\sim0.5$的时候，我就采取a2；当x属于$0.5\sim1$的时候 我就采取action a3；大概是这样一个意思

## 基本概念-Part2

### Reward

**下面我们来介绍另外一个概念叫reward，**

Reward是强化学习当中非常有独特性的一个概念
Reward是什么呢？首先它是一个数，它是一个实数，它是一个标量，在agent采取了一个动作之后它会得到这样一个数

这个数是有一定含义的

如果这个数是正数 代表我们对这样的行为是鼓励的

如果这个数是一个负数代表我们不希望这样的行为发生

实际上是对行为的一个惩罚

**这里有两个问题** 

<u>第一个就是如果我不给它reward，或者说这个reword设为0的话会代表什么？</u> 

这个相对来说会比较复杂，不过总的来说就是没有punishment，没有punishment在一定程度上就是会鼓励

**另外一个就是我们能不能用正数来代表punishment，用负数来代表鼓励？** 

实际上是可以的 实际上是一种数学上的技巧，本质上来说得到的东西是一样的

- 如果正数是代表鼓励的话，Agent希望能够得到越来越多的正数
- 如果正数代表惩罚的话，Agent自然要minimize这样的惩罚，得到越来越少的惩罚

比如说举个例子，在我们这个grid-world example当中，我们是这样设计reward的，

- 如果agent想要去逃出四周的这样一个边界，每次它有这样的动作的时候，我们就会给它一个负数 r boundary=-1
- 如果agent是要进到forbidden area里面去，有这样的倾向的时候 我们会给它 r forbid=-1
- 如果agent进到了target area，那么由于到达了目标，我们会给它鼓励，让它的r target=+1，其它的所有agent采取的行动得到的reward都是0，比如说它从这走到这，比如说它在原地保持不动等等，这些reward都是0

Reward，实际上是可以被理解成是一个human-machine interface，什么意思？实际上是我们和机器进行交互的一种手段，因为reward设计相对来说是还是比较直观的，所以我们就可以引导agent，我们告诉它，它应该怎么样做，不应该怎么样做，比如说在上面的例子当中，通过设计这样的reward，Agent就不会去跑出边界，不会要进到forbidden area。

它会怎么做？它会尽量地去进到target area，所以我们可以通过设计reward来实现我们的目标，我们也可以用tabular representation来表示reward

![image-20260508151327050](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605081659353.png)

同样的这个表格它的每一行对应的是一个状态，它的每一列对应的是一个action，比如说在这样一个状态s1当中，我采取了action a1，我得到的一个reward的就是r boundary，这个表格相对来说还是比较直观的，但是它的问题就是说它应用的还是比较有限的

为什么？因为它只能来表示determinisric的情况

什么是determinisric？就是说我在一个状态，我采取了一个行动，我一定会得到一个什么样的reward，但是实际上可能会得到reward的大小是不确定的，这时候是一种不确定的状态 那么表格的形式就不再适用了。

**这时候我们可以用一种更加一般化的方法，那就是数学的方法 用什么呢？** 

还是和之前一样 就是用条件概率。比如说我们举一个例子在状态s1，如果我们选择了action a1，它要是往上走，这时候它的reward就是-1，这个是直观的，它的数学是什么呢？$p(r=-1|s_1,a_1)=1$、$p(r \neq -1|s_1,a_1)=0$ 

- 就是我在s1 我选择a1 我得到-1的probability是多少？是1
- 我得到不是-1的probability是多少？是0，所以这个其实也是确定性的

<u>我在这个状态采取这个行动，我一定会得到那个reward，我刚才提到了其实也会存在这种stochastic这种reward</u>

比如说我们学习得非常地努力 那么我一定会得到reward，但是我能得到多少reward 可能是有很多因素所决定的，这可能是有一定随机性的，但是我们努力学习这样一个action还是值得我们去鼓励的，所以一定会得到一个正的reward，究竟多少的话，具体的值可能是不确定的

### Trajectory

**好 下一个概念就是叫Trajectory 、Trajectory是什么？**

其实刚才我们也提到了，它实际上是一个叫**state-action-reward一个链**

### discounted return

**好 下面一个概念非常重要叫discounted return**

- 如果γ比较大的话 它会变得更加远视，它会更加注重长远的这种reward

### episode

**什么是absorbing state？** 

就是我们在设置它的stage transition probability的时候，就是如果当前的这个状态就是这个target的状态，那么不论你采取什么样的action它都会再回到这个状态，或者说在这个状态的时候，它就没有其它的action 我可以修改它的action space，让它的action只有留在原地这样一个action

所以通过这种方法，其实我们就可以实现这种把episodic转换成continuing task，当然我们还要再修改一下，就是它之后所得到的所有的reward全都是0

首先看轨迹，那它会跳到这边 然后跳到这边，然后根据策略跳这边，然后再跳到这边 ，对吧， 然后之后它还会继续走，会一直这样无穷地走下去， 所以这个是它的轨迹，那这轨迹它对应的return ，首先是r1加上r2γ，加上γ的平方r3，然后加上γ的立方r4等等，那这是一个非常简单的一个定义；

所以其它的v2也是一样 ，就r2加上γr3加上γ平方r4，那么接下来的这些非常简单都可以用定义写出来

直观就是说我从这出发然后会跳到这，在这个过程当中首先我会得到r1，然后我跳到s2，其实我后边的就不用再走了，还有很长的我要走，没有关系，我知道我跳到s2 ，从这出发我得到的return一定是v2，那所以这个v1就等于r1加上γv2 还是比较容易理解的

### State value

刚才我们通过两个例子，分别介绍了为什么return是重要的以及怎么样计算return，下面我们来正式地介绍state value这样一个概念，为了介绍state value我们首先要引入一些符号

$S_t \xrightarrow{A_t} R_{t+1},S_{t+1}$



首先我们看这个比较简单的单步的这样一个过程，这里边St指的是当前的状态，然后在当前的状态下我采取的动作是At，我得到的下一个reward是Rt+1 ，跳到的下一个状态是St+1，这里边$t$指的是当前的时刻， t+1指的是下一个时刻，那么它们具体的这个含义都在这里写着

![image-20260508200229490](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605082051370.png) 

这里边值得指出的是有时候我们也会把Rt+1写成Rt，也就是在St我采取At我得到的reward是Rt，当然一般来说我们都写成Rt+1，从数学上来说它们没有什么本质的区别 ，这个只是一个习惯。

注意字里面所有的S A和R它们全是大写，那它们就代表了random variable 所谓random variable，就是我们可以对它们求一系列的操作，比如说像常见的expectation

![image-20260508200351534](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605082051073.png) 

- 另外在这个过程当中 ，所有的这些跳跃，它们都是由probability distribution来决定的；
- 比如说我在St我要采取什么样的动作，就是由策略来决定的；
- 我在St ，我take action At 我要得到什么样的reward，这个就是由这个reward probability来决定的；
- 我在St ，我采取At 我要跳到下一个什么状态，这个就是由state transition probability来决定的

这样一个单步的策略 单步的过程，可以推广到一个多步的trajectory

![image-20260508200556269](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605082051688.png) 

我从St出发， 然后我take action At 我跳到下一个状态，我得到一个reward 然后这样持续下去，就得到了这样一个multi-step trajectory，对这个trajectory，我们当然可以求discounted return

![image-20260508201507505](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605082051222.png) 

我们用这个符号大的Gt来代替，那它就是对这些immediate reward的一个相加，但是这里边要考虑这个discounted rate γ

因为这里边Rt+1 Rt+2等等全都是random variable，所以Gt也是一个random variable 随机变量

有了刚才这些准备我们下面就可以来正式定义state value，实际上state value非常非常地简单

我们知道Gt是对一个trajectory它的discounted return

==state value是什么呢？== **就是Gt的expectation 期望值，或者它叫expected value 或者叫mean 或者叫average，它们实际上都代表同一个意思 ，就是平均值** 

![image-20260508201713938](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605082051669.png)

- state value的全称叫state-value function；简称叫state value 我们用这个$v_π(s)$ 来代替state value
- 它数学的定义就是对Gt的求expectation，但是它是一个conditional expectation，也就是当前的状态应该取一个具体的值s

这里边有几点我们要说明，

① 首先这个 $v_π(s)$ ，它是s的这样一个函数，所以从不同的s出发， 我得到的轨迹不同，那显然得到的discounted return也不同，我求平均也是不同的
② 第二， 它是一个策略的函数， 函数我们可以这样写 $v(\pi，s)$ ，我把π放成一个变量放到括号里边；但是为了简单起见我们就写成 $v_π(s)$  ，把这个 π 放到下标

显然不同的策略我会得到不同的轨迹，那不同的轨迹又会得到不同的return，进而会得到不同的state value；另外 state value 这个value不仅仅是一个数值的value，它也代表它的一种价值， 当一个state value比较大的时候，就代表这个状态是比较有价值的，因为从这个状态出发 我会得到更多的return

下面我们来回答这个问题，就是return和state value有什么样的区别？

实际上在刚才的motivating example，我们反复提到了是return 现在我们在定义的是state value，它们究竟有什么区别和联系呢？其实非常简单

Return是针对单个trajectory我求的return，而state value是对多个trajectory，我得到的return再求平均值

如果我从一个状态出发， 我有可能得到多个trajectory，这时候return和state value显然是有区别的，但是如果我从一个状态出发一切都是确定性的，我能够只能够得到一条trajectory，这时候从那个状态出发得到return和那个状态的state value就是一样的

下面我们来看3个例子 这3个例子也是我们刚才motivating example里边见到的3个例子

![image-20260508202301261](https://cdn.jsdelivr.net/gh/dearRongerr/PicGo@main/202605082050589.png)



首先这3个例子分别对应3个策略π1 π2 π3；我们下面要计算什么呢？

计算在这三个不同策略下 ，同一个状态s1，它们的state value 实际上这个计算非常地简单

因为第一个， 它的state value  ，我从这出发，我会得到唯一的一条trajectory，这个trajectory的return就是它的state value，这个之前我们已经计算过了

第二个state value也很简单， 那就是沿这条轨迹的return

第三个稍微麻烦一点 它会有两条轨迹，state value是这两条轨迹分别得到return的一个平均值，怎么个平均法呢？就是把前面的probability乘到前面去，这个实际上就是一个expectation的求法，得到的是这样一个值，显然我们知道vπ1是最大的， vπ2是最小的， vπ3是居中的；所以我们知道第一个策略是最好的 第二个策略是最差的
